Смотри, есть файл exmples/log_tz_short.md. Посмотрим на него. Это Markdown-файл. Он содержит в себе техническое задание для логирования. 
Он состоит из заголовков и таблиц. Иногда могут встречаться тексты вне таблиц и вне заголовков, но их будем воспринимать аналогично заголовкам.
В том виде, в котором это существует, оно неудобно для работы. Я хочу составить сводную таблицу, которая агрегирует всю эту информацию. Результирующая таблица не должна быть в формате Markdown. Мы сформируем json, а далее мы будем рендерить в нужном нам формате. Для начала, пусть результатом рендера будет просто HTML-таблица.

В тз есть таблицы есть двух типов:
- Есть таблицы, состоящие из трёх колонок(Поле, Описание, Значение). Назовём их тип-1;
- Есть же таблицы с другим количеством колонок, в них преобладают значения вида "О", "НО". Назовём их тип-2.


Из таблиц "тип-1" мы возьмём основные данные:
- Данные из столбца "Поле" позволят нам сформировать нам название столбцов результирующей таблицы. Столбцы не должны дублироваться;
- Данные из столбца "Описание" позволят нам сформировать описание столбцов, которое разместим во второй строке результирующей таблицы. В случае разных описаний для одного поля, мы разместим их через символ "/", мы не должны их терять;
- Данные из столбца "Значение" будут формировать строки таблиц, располагаясь в соответствующих столбцах;
- Таким образом каждая таблица типа 1 сформирует строку таблицы и, возможно, дополнит набор столбцов и их описаний.


Заголовки и тексты вне таблиц будут формировать строки таблиц, располагаясь в первом столбце, оставляя остальные столбцы пустыми.

Из таблиц "тип-2" мы возьмём дополнительные данные:
- Первый столбец содержит описание события. Это соответствует значению action какой-то из строк выше;
- заголовки последюущих столбцов содержат дополнительные столбцы для результирующей таблицы;
- О/НО попадут в строку события, обозначая обязательные и необязательные поля события.

Разработку будем вести на html, css, js(typescript) в файле js-tbl.html

Те таблицы, которые не удалось отнести к какому-либо типу, мы просто в неизменном виде будем выводить внизу страницы, как markdown код.

При реализации пусть будут такие сущности:
- парсер markdown, на выходе дающий json вида {"converted": [{"type":"text", "content":"parsed_text_value"},{"type":"text", "content":"parsed_text_2_value"}, {"type":"table","tableType":"type-1", "rows":[...] , "colCnt":int},{"type":"text", "content":"parsed_text_3_value"}, {"type":"table","tableType":"type-2", "rows":[...] , "colCnt":int}]} и json с ошибками парсинга(проблемный фрагмент + причина ошибки)
- Компилятор сводной таблицы, работающий с jsonom из парсера, генерирующий свой json
- Рендерер в html таблицк
