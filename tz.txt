# ТЗ: Парсер лог-ТЗ → Сводная таблица (HTML) — v2

## 1. Цель

Написать SPA, которая:
1. Парсит Markdown-файл ТЗ по логированию (примером является содержимое `examples/log_tz_short.md`).
2. Группирует таблицы type-1 и type-2 в пары (группы).
3. Мерджит O/NO значения из type-2 в соответствующие строки type-1.
4. Выводит результат как HTML-таблицу с поиском и экспортом (CSV/JSON).
5. Выводит внизу необработанные (unknown) таблицы в `<details>`.

---

## 2. Формат входного файла

Markdown-файл использует **нестандартный табличный синтаксис** (не GitHub-flavored Markdown):

### 2.1. Маркеры границ

| Маркер (отдельная строка) | Роль |
|---|---|
| `#|` | **Начало** таблицы |
| `\|\|` | **Разделитель строк внутри** таблицы (конец одной строки + начало следующей). В паре `\|\|\n\|\|` — просто граница между двумя строками |
| `|#` | **Конец** таблицы |
| `\|` (одиночная) | **Разделитель ячеек** внутри строки |

**Важно:** вложенных таблиц нет. Строки `\|` внутри таблицы — всегда разделители ячеек. Строки `\|\|` внутри таблицы — всегда разделители строк.

### 2.2. Типы контента

| Тип | Как выглядит | Пример |
|---|---|---|
| **Заголовок H1–H6** | `# Текст` | `# ТЗ на логирование...` |
| **H5-заголовок** | `##### Текст` | `##### 1.1.1 Нажатие на "Добавить все"` |
| **Блок-маркер** | `{% cut "..." %}` | `{% cut "(1.1. \"Добавить все\")" %}` → превращается в H2 |
| **Table type-1** | `#|` … `|#` (3 колонки: Поле, Описание, Значение) | Описание полей конкретного события |
| **Table type-2** | `#|` … `|#` (множество колонок, значения О/НО) | Матрица action × поле с обязательностью |
| **Текст** | Всё, что вне таблиц, вне заголовков и блоков `{% cut %}` | Обычный текст |

### 2.3. Пример таблицы type-1

```
#|
||
**Поле**       |  **Описание**                        |  **Значение**
||
||
**Название**   |  Название события (уникальный action). |  click_add_all
||
||
**id_element** |  Важный параметр                     |  recipe_products
||
||
**button_name**|  Важный параметр                     |  <Добавить все>
||
||
|#
```

### 2.4. Пример таблицы type-2

```
#|
||
&nbsp;   |  click_add_all  |  show_popup  |  add_product  |  ...
||
||
qty       |  О |  НО |  О  |  ...
||
||
stock     |  НО |  О |  НО |  ...
||
||
color     |  О |  О  |  НО |  ...
||
||
|#
```

**Структура type-2 (индексы строк по массиву parsed rows):**
- **Row 0** (первая строка): заголовки столбцов — action-имена (ключи для merge и для вывода type-2 таблицы). Первая ячейка — пустая или `&nbsp;` (заглушка).
- **Rows 1+** (data body): `[column1_value, value_for_action1, value_for_action2, ...]`.
  - Column 1 (первая ячейка каждой строки) — имя поля (например, `qty`, `stock`, `color`...), которое станет ключом столбца в type-1.
  - Остальные ячейки — значения для каждого action (обычно О/НО, но могут быть и другие данные).
  - Если во время merge с type-1 в ячейках rows 1+ встречаются не О/НО → **ошибка в лог**, строка пропускается.
  - Если type-2 не имеет matching type-1 action → строка просто рендерится в type-2 таблице без merge.

## 3. Алгоритм

### 3.1. Pipeline обработки

```
Parser (cleanup + parse) → PostProcessor (group) → Compiler (merge + output) → Renderer
```

### 3.2. Parser (внутри `parse()`)

1. **Разбить текст на строки.**
2. **Найти границы таблиц:** `#|` → `|#`. Внутри: `\|\|` — разделитель строк.
3. **Извлечь ячейки:** разбить по `\|`, санитайз.
4. **Классифицировать таблицу:**
   - Заголовки = {"Поле", "Описание", "Значение"} (регистронезависимо) → **type-1**
   - Есть ячейки с "О" или "НО" → **type-2**
   - Иначе → **unknown**
5. **Собрать не-табличный контент:**
   - `^#+\s` → **header** (с уровнем)
   - `{% cut "..." %}` → **header** level 2 (контент изнутри)
   - Остальные непустые → **text**
6. **Очистка ячеек таблиц** (`sanitize()`): убрать `**`, `&nbsp;`, `\`, `\{`, `\}`, `[`, `]`, `\|`, `\n`, ведущий/хвостовой пробел (`trim`).
7. **Очистка текстовых нод** (внутри `parse()`):
   - Убрать `**` из `TextNode.content`
   - `{color}(...)` → оставить только `(...)` (внутреннее содержимое, без `{color}`), где color соответствует регулярке `(gray|yellow|orange|red|green|blue|violet)`
8. **Собрать ошибки.**

### 3.3. PostProcessor (группировка)

1. **Stack-based grouping:**
   - Идём по `ParsedItem[]` последовательно.
   - Встретили **type-1** → пушим на стэк (присваиваем `groupIndex`).
   - Встретили **type-2** → назначаем тот же `groupIndex` всем тип-1 на стэке, затем очищаем стэк.
   - Встретили **unknown** → ошибка.
2. **Flush remaining:** если после конца файла на стэке остались type-1 — они получают новый `groupIndex` (группа без type-2).
3. Результат: `GroupedResult { groups: { type1Items: [...], type2Item: TableNode | null }[] }`

### 3.4. Compiler (merge + output)

#### 4.1. Group type-1

Для каждой type-1 таблицы:
1. Первая строка данных — заголовки колонок (Поле / Описание / Значение).
2. Для каждой строки:
   - `"Поле"` → ключ столбца
   - `"Описание"` → описание столбца
   - `"Значение"` → заполнение ячейки
3. Каждая type-1 таблица → **одна строка** результирующей таблицы.

#### 4.2. Group merge (type-2 → type-1)

Для каждой группы:
1. Если группа имеет type-2 таблицу:
   - **Row 0** type-2 → массив action-имён (заголовки столбцов). Первая ячейка пропускается. Эти action-имена добавляются как новые столбцы в group.columns.
   - **Rows 1+** (data body): для каждой строки:
     - Column 1 = имя поля (ключ для merge и для вывода type-2 таблицы).
     - Остальные ячейки = значения для каждого action (обычно О/НО).
     - Если ячейка содержит не О/НО → **ошибка в лог**, строка пропускается.
     - Если action из row 0 type-2 не найден ни в одной type-1 строке → **ошибка в лог**.
   - **Merge** (для каждой строки type-1):
     - Найти action-имя в type-1: в row type-1, где `"Поле"` = `"Название"`, взять `"Значение"`.
     - Найти matching type-2 row (по column 1 = имя поля).
     - При совпадении → записать все О/НО значения из type-2 строки в type-1 строку (под соответствующие action-столбцы).
2. Сформировать колонки группы = колонки type-1 + добавленные action-колонки из type-2 (если есть).

#### 4.3. Output format

Каждая группа выдаёт:
- **Type-1 rows:** строки type-1 с merged action-колонками. Колонки = только для этой группы.
- **Type-2 rows:** если в группе есть type-2 → вывести все rows 1+ type-2 как отдельную компактную таблицу:
  - Колонки = action-имена из row 0 type-2 (без первой пустой ячейки) + столбец `column1_value`.
  - Каждая строка = `[column1_value, value_for_action1, value_for_action2, ...]`.

#### 4.4. Текстовые строки и заголовки

Каждая текстовая строка / заголовок вне таблиц → отдельная строка:
- Размещаются **в порядке встречи** в файле (между строками группы).
- Первый столбец → `content` (или `level + ": " + content`).
- Остальные столбцы → пустые.

## 4. Рендерер

### 4.1. Сводная таблица (по группам)

Для каждой группы:
- **Заголовок группы:** `h2` из первой type-1 строки (или section header).
- **Столбцы:** названия колонок (`label`) из `group.columns`.
- **Type-1 rows:** данные из `type1Rows[]`.
- **Type-2 rows:** данные из `type2Rows[]` (если есть) — отдельная компактная таблица сразу после type-1.
  - **Колонки type-2 таблицы = всё своё содержимое, без type-1 полей.**
  - Рендерим все rows 1+ type-2 таблицы подряд.

Стилизация:
- Границы, padding, sticky header, hover-эффект на строках.
- "О" → зелёный бейдж (`.badge-ok`), "НО" → жёлтый бейдж (`.badge-no`).

### 4.2. Секционные заголовки

- Каждый header → `<tr>` или `<div>` с отступом по `level`.
- Размещаются между строками группы в порядке встречи.

### 4.3. Необработанные таблицы

- Для каждой unknown → `<details><summary>Неизвестная таблица (N строк)</summary><table>...</table></details>`
- Разместить внизу страницы.

### 4.4. Поиск и экспорт

- **Поиск:** поле `<input type="text">` вверху, фильтрация строк.
- **Экспорт CSV/JSON:** кнопки, генерация из текущих данных.

## 6. Ограничения и договорённости

| Аспект | Решение |
|---|---|
| Вложенные таблицы | Не поддерживаются |
| Пустые ячейки | OK, `trim()` |
| Регистр заголовков type-1 | Нечувствительно к регистру |
| `{color}(...)` → `(...)` | В cleanup внутри Parser |
| `{% cut "..." %}` → H2 | В cleanup внутри Parser |
| `**` в TextNode | Убирается в cleanup внутри Parser |
| `**` в ячейках | Убирается в sanitize() |
| Escaped `\*` | Не трогать |
| Несовпавший action (type-1 → type-2) | Несовпавший action → ошибка в лог |
| Тип-1 без type-2 | Выводится без дополнительных колонок |
| Пер-групп колонки | Каждая группа имеет свои колонки |
| Зависимости | TypeScript — HTML/CSS/JS, без фреймворков |
| Загрузка файла | `<input type="file">` |

Работу ведём в файлах:
- `src/ts/*.*` (любые файлы внутри ts)
- `public/css/*.*` (любые файлы внутри css)
- `public/index.html`

## 7. Порядок выполнения (актуализированный)

1. **HTML-скелет** — загрузка файла, контейнеры, CSS (✅ Готово).
2. **Parser** — парсинг Markdown + cleanup (`**`, `{color}`, `{% cut %}` → H2) (⚠️ Требует изменений).
3. **PostProcessor** — группировка type-1/type-2 через стэк (🆕 Новый модуль).
4. **Compiler** — per-group merge O/NO, per-group columns, output type-1 + type-2 rows (⚠️ Требует изменений).
5. **Renderer** — per-group table rendering, type-2 as separate compact block (⚠️ Требует изменений).
6. **Поиск/экспорт** — фильтрация строк, CSV/JSON (⚠️ Требует адаптации к per-group).
7. **Unknown tables** — вывод внизу в `<details>` (✅ Готово, но может потребовать адаптации).
